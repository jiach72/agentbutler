**「关于」页修复与简化（两件事：让更新按钮出现 + 页面减负）**

一、修复更新按钮不出现的根因（发版链路断裂）
1. 版本 beta.23 → beta.24（21 处 + CHANGELOG 补记），提交后打 tag `v1.0.0-beta.24` 并连 tag 推送 GitHub——使 `git ls-remote --tags` 能发现高于当前运行版本的 tag，升级按钮随之出现。
2. 更新默认通道 `stable` → `beta`：apps/watch/src/self-upgrade.ts 默认值、http.ts prefs 缺省、UI 偏好显示同步修改（本项目发布全部为 beta tag，stable 默认会永久隐藏按钮）。

二、关于页简化（VersionsPanel.tsx 重排，纯前端）
- 常驻仅保留：①「管家自身」主卡（版本+检测状态+升级/回滚按钮+通道偏好）②「受管实例与可升级版本」合并卡 ③「退回上一版本」紧凑行。
- 「升级进度」「升级前检查」改为仅任务运行/有内容时渲染；「备份节奏图」移入底部折叠「高级」区。默认可见卡片 7 → 3~4。

三、验证与收尾
- tsc + ui 测试；deploy.sh 部署；线上核验 /api/butler/self 候选含 beta.24、按钮出现、卡片密度下降；推送 GitHub（提交+tag）并同步 WSL。
- 备注：tag 与当前部署代码同源，面板上点「升级」仅对齐版本号并重启服务，无实际风险；是否执行由你在面板决定。
